# @layertwo/cdk-constructs

Reusable [AWS CDK](https://aws.amazon.com/cdk/) constructs with secure defaults baked in, for TypeScript projects.

Published to GitHub Packages as a JSII library. Only the TypeScript/JS package is published.

## Installation

The package lives on GitHub Packages, so point the `@layertwo` scope at it (`~/.npmrc` or project `.npmrc`):

```ini
@layertwo:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

Then:

```bash
npm install @layertwo/cdk-constructs
```

## Constructs

| Construct | Extends | Enforced behaviour |
| --- | --- | --- |
| `SecureBucket` | `s3.Bucket` | Blocks all public access, S3-managed encryption, SSL enforced. Versioning on by default (`versioned: false` to opt out). |
| `SecureTable` | `dynamodb.Table` | On-demand billing (`PAY_PER_REQUEST`), point-in-time recovery always enabled. |
| `GitHubOidcRole` | `iam.Role` | Role assumable by GitHub Actions via OIDC, scoped to a repo and optionally a branch or environment. |
| `DnsValidatedCertificate` | `certificatemanager.Certificate` | Always DNS-validated against the supplied Route53 hosted zone. |
| `PythonFunction` | `lambda.Function` | Bundles a `uv` project in Docker, hashes the source tree (no re-upload when nothing changed), ARM64 + Python 3.15 by default. |

Everything marked *enforced* is hardcoded after your props are spread in — passing your own value for it is silently ignored. All other props pass straight through to the parent construct.

## Usage

```typescript
import * as path from "node:path";
import {
  DnsValidatedCertificate,
  GitHubOidcRole,
  PythonFunction,
  SecureBucket,
  SecureTable,
} from "@layertwo/cdk-constructs";
import { HostedZone } from "aws-cdk-lib/aws-route53";

// S3: public access blocked, encrypted, SSL-only, versioned
const bucket = new SecureBucket(this, "Assets");

// DynamoDB: on-demand + PITR
const table = new SecureTable(this, "Sessions", {
  partitionKey: { name: "id", type: dynamodb.AttributeType.STRING },
});

// IAM role for a GitHub Actions workflow on main
const deployRole = new GitHubOidcRole(this, "DeployRole", {
  owner: "layertwo",
  repo: "my-app",
  branch: "main",
});

// ACM certificate validated via Route53
new DnsValidatedCertificate(this, "Cert", {
  domainName: "example.com",
  hostedZone: HostedZone.fromLookup(this, "Zone", { domainName: "example.com" }),
});

// Python Lambda from a uv project (built in Docker at synth time)
new PythonFunction(this, "Fetcher", {
  rootDir: path.join(__dirname, "../services/fetcher"),
  index: "src/entrypoint/__init__.py",
  handler: "handle_event",
  environment: { TABLE_NAME: table.tableName },
});
```

### Python bundling and caching

`PythonFunction` builds inside an Amazon Linux 2023 container (glibc matches Lambda), so it needs Docker at synth time. The asset is fingerprinted from the project source — `uv.lock` changes rebuild it, caches and `.venv` do not.

Two things make that fast in CI:

```yaml
# Skip bundling entirely when the source hash matches a previous run.
- uses: actions/cache@v4
  with:
    path: cdk.out
    key: cdk-assets-${{ github.sha }}
    restore-keys: cdk-assets-

# Cache the image layers; type=gha needs BuildKit, and fails on a plain local daemon.
- uses: docker/setup-buildx-action@v3
```

```typescript
const cacheScope = "lambda-bundling";
new PythonFunction(this, "Fetcher", {
  rootDir,
  bundling: process.env.CI
    ? {
        cacheFrom: [{ type: "gha", params: { scope: cacheScope } }],
        cacheTo: { type: "gha", params: { mode: "max", scope: cacheScope } },
      }
    : {},
});
```

The default image has no C toolchain: dependencies without a manylinux wheel fail at bundling instead of shipping a broken bundle. Pass `bundling.image` to use your own build image.

## Development

This project uses [Projen](https://projen.io/) for configuration and build management. Configuration lives in `.projenrc.ts`.

### Setup

```bash
yarn install
npx projen          # regenerate project files from .projenrc.ts
```

Node.js 22 or 24 (the versions jsii supports). Dependency upgrades arrive as Renovate PRs — there is no local upgrade task.

### Common commands

```bash
npm run build       # full build: compile (jsii) + test + package
npm run compile     # compile TypeScript only
npm test            # tests with coverage
npm run test:watch  # tests in watch mode
npm run eslint      # linter
npm run package     # generate distributable packages
npx projen          # re-synthesize generated files
```

### Making changes

1. Add the construct in `src/` and export it from `src/index.ts`.
2. Add a matching `test/<name>.test.ts` using CDK assertions.
3. Run `npm run build`.
4. For build/config changes, edit `.projenrc.ts` and run `npx projen`.

Do not edit files marked `~~ Generated by projen` — change `.projenrc.ts` and regenerate instead.
