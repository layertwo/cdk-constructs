# Project Structure

## Directory Layout

```
.
├── src/                    # Source code for CDK constructs
│   ├── index.ts           # Main entry point, exports public API
│   └── *.ts               # Individual construct implementations
├── test/                   # Jest test files
│   └── *.test.ts          # Test files matching src structure
├── lib/                    # Compiled JavaScript output (generated)
├── dist/                   # JSII package output (generated)
├── coverage/               # Test coverage reports (generated)
├── test-reports/           # JUnit test reports (generated)
├── .projen/                # Projen metadata (generated)
├── .github/                # GitHub workflows and configuration
├── .kiro/                  # Kiro AI assistant configuration
│   └── steering/          # AI assistant steering rules
├── node_modules/           # Dependencies (not committed)
├── .projenrc.ts           # Projen configuration (source of truth)
└── API.md                 # Auto-generated API documentation
```

## Key Files

- **`.projenrc.ts`**: Project configuration source. Modify this to change build settings, dependencies, or project metadata.
- **`package.json`**: Generated by Projen. Contains scripts, dependencies, and package metadata.
- **`tsconfig.dev.json`**: TypeScript configuration for development (generated).
- **`src/index.ts`**: Main entry point. All public exports must be declared here.
- **`API.md`**: Auto-generated API documentation from JSDoc comments.

## Code Organization

### Source Code
- Place all construct implementations in `src/`
- One construct per file (e.g., `github-oidc.ts`)
- Export all public APIs through `src/index.ts`
- Use clear, descriptive names for constructs and files

### Testing
- Mirror source structure in `test/` directory
- Name test files with `.test.ts` suffix (e.g., `github-oidc.test.ts`)
- Use CDK assertions library for infrastructure testing
- Group related tests with `describe()` blocks
- Keep tests focused and composable

### Construct Development Patterns
- Extend appropriate CDK base classes (e.g., `Role`, `Construct`)
- Define props interfaces with JSDoc comments
- Use `readonly` for all props
- Provide sensible defaults where appropriate
- Document all public APIs with JSDoc

## Generated Files (Do Not Edit)

Files with the header `~~ Generated by projen` are automatically generated:
- `package.json`
- `tsconfig.dev.json`
- `tsconfig.json`
- `.eslintrc.json`
- `.gitignore`
- `.npmignore`
- GitHub workflow files in `.github/`

To modify these, update `.projenrc.ts` and run `npx projen`.

## Build Artifacts (Ignored by Git)

- `lib/` - Compiled JavaScript and type definitions
- `dist/` - JSII packages for all target languages
- `coverage/` - Test coverage reports
- `test-reports/` - JUnit XML test reports
- `node_modules/` - Dependencies
